## 視覺要求
參考 PURE IN 官網，延續暖米白、陶土棕、灰棕、細線、寬鬆留白與拱形照片。
- 背景 #FFFCF9；主要按鈕 #895638；文字 #6E5A50；輔助 #897870；資訊底 #F1EEE7；線條 #DFD5CA。
- 中文內文 Noto Sans TC；中文標題 Noto Serif TC；英文 Playfair Display。
- 照片使用 images/clinic.png；標誌使用 images/logo.svg，保留比例與 SVG 清晰度。
- 直接參照 CSS 的字體、間距與斷點。請檢查文字對比度、鍵盤焦點、觸控尺寸及窄螢幕可讀性。
- 左側頁面編號選單、桌面/手機切換、DESIGN PREVIEW 是提案展示工具，不要放進正式產品。

## 頁面與操作
首頁、登入、客戶資料、項目、日期時段、確認、完成、我的預約、預約詳情；後台為總覽、醫師班表、項目營業、帳號權限。
前台循序漸進，每一步只呈現當下必要資訊，返回時保留填寫資料。「負責業務」下拉選單放在客戶資料最前方。桌面可有摘要；手機優先呈現表單。

## 已指定營業規則
週一至六 10:00–19:00；週日休診。每筆 60 分鐘，每日 9 個起始時段（10:00 至18:00）；同一時段全院只能一筆有效預約。
週二廖醫師 13:00–19:00；週四嚴醫師 13:00–19:00；週五醫師未定 10:00–17:00。
項目：健保、自費、療程諮詢、例行保養與療程、點滴／針劑、疫苗、其他。
官網週六寫至17:00，但使用者先前指定19:00，本提案採19:00；正式上線需確認統一。不要自行推定每個項目需要哪位醫師，須建立可設定的醫師需求對應。

## 原型不能直接當正式邏輯
prototype/app.js 僅為視覺示範：硬編日期、示範帳號、不驗證密碼、無持久化、修改會新增展示紀錄、後台僅提示訊息。請替換，不照搬這些限制。
正式系統應有：服務端登入、密碼雜湊、角色授權、業務只能存取自身預約、管理者管理全部；資料庫持久化；新增/改期的原子防重複檢核；取消及稽核紀錄；台北時區與過期日期限制；醫師時段、營業與封鎖時段交集檢核；友善的錯誤、空白、載入及成功狀態。
不要將所有 UI 畫成一張背景圖，需以可操作的 HTML/框架元件實作；不要寫入真實客戶資料或憑證。
